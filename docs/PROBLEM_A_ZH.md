# 2026 MCM 高级组 A 题：SafeInvest

> 本文用于团队理解题目和讨论解题路线，包含题目中文翻译及初步方案。第 1 节依据赛题原文翻译；后续章节是建模建议。本文尚未进行策略回测，所有候选配置、指标和规则均不能视为已验证结论。

## 1. 题目中文翻译

原题：**SafeInvest: Building a Trustworthy Robo-Advisor（构建值得信赖的智能投顾）**。

原始输入文件为 `2026_MCM_SafeInvest.pdf` 和 `SafeInvest_Synthetic_Data.csv`。本次文档提交不包含这两个文件；由主 AI 获取原始文件并在仓库中记录实际位置和来源。最终以英文赛题为准。

### 1.1 背景与挑战

SafeInvest 是一家虚构的金融科技公司，通过手机应用提供投资建议。新客户完成一份简短的数字问卷，自动化系统随后推荐以下三种投资组合之一：

- 保守型（Conservative）；
- 均衡型（Balanced）；
- 成长型（Growth）。

每种组合均使用股票、政府债券和一种类似现金的短期投资资产。客户投资后，应用每期检查一次组合，可以保持当前持仓、进行再平衡、改变目标配置，或请求人工顾问审核。

自动化能够降低投资建议的成本并扩大覆盖范围，但也带来了新风险：组合可能不适合客户，算法可能交易过于频繁，建议也可能难以解释。系统还必须识别哪些情况下不应信任模型。

本题要求开发并检验一套自动化、可解释且重视风险的智能投顾流程。它必须推荐合适的组合，仅在预期收益足以证明成本合理时才调整组合，并识别需要人工审核的决策。

### 1.2 客户信息

问卷记录投资期限、客户认为自己能够承受的最大暂时性购买力损失，以及流动性需求。五个代表性客户如下：

| 客户 | 投资期限 | 损失容忍度 | 流动性需求 |
|---|---:|---:|---|
| A | 5 年 | 10% | 高 |
| B | 15 年 | 25% | 中 |
| C | 30 年 | 40% | 低 |
| D | 25 年 | 15% | 中 |
| E | 6 年 | 35% | 高 |

**损失容忍度是客户的问卷回答，不是组合能够保证的损失上限。**

### 1.3 提供的市场数据

数据包含 180 个相互独立的合成市场情景，每个情景包含 30 个年度期间。

| 字段 | 中文含义 |
|---|---|
| `scenario_id` | 情景编号，1–180 |
| `period` | 情景内年度编号，1–30 |
| `equity_return` | 股票名义总收益率 |
| `bond_return` | 政府债券名义总收益率 |
| `bill_proxy_return` | 短期票据代理资产名义收益率 |
| `inflation` | 当期通胀率 |

收益率和通胀率以小数表示，例如 `0.05` 表示 5%。名义收益率为 `r`、通胀率为 `π` 时，实际收益率为：

```text
实际收益率 = (1 + r) / (1 + π) - 1
```

这些数据依据美国历史市场数据合成，**不代表真实历史事件，也不是市场预测**。

### 1.4 共同条件

1. 每个市场情景初始拥有 100 单位资金，全部投资于短期票据；之后没有新增存款或提款。
2. 组合只能做多，且必须全额投资，不能卖空或加杠杆。
3. 每期最多检查组合一次；数据中一期为一年。
4. 交易费用为资产之间转移金额的 **0.25%**。同一笔转移只计算一次。例如，从票据转移 20 单位至股票，费用为 `20 × 0.0025 = 0.05` 单位。
5. 费用在交易发生时从组合财富中扣除，然后才应用当期收益率。初始从票据配置到其他资产也需要收费。
6. 忽略税收、其他费用，以及期末清算费用。
7. 第 `t` 期决策只能使用该情景截至第 `t-1` 期的观察值，不能使用第 `t` 期或之后的信息。

### 1.5 任务一：设计数字化客户适配流程

选择投资增长与风险指标。严重损失指标必须满足：**数值越大，损失越严重**。风险评估要区分一般波动和异常严重损失，并考虑购买力。

为保守型、均衡型、成长型推荐配置比例或配置规则。设计透明的开户评估规则，根据问卷推荐其中一种组合，或要求人工审核。将规则应用于客户 A–E，并简要解释。

### 1.6 任务二：设计并评估自动化组合策略

针对被分配至均衡型组合的客户，设计一套规则，决定：

- 保持当前持仓；
- 再平衡；
- 改变目标配置；
- 请求人工审核。

只有在估计收益足以覆盖交易成本时，才交易或改变目标配置。

使用如下基准进行比较：股票、债券、票据的目标权重始终各为三分之一，每次检查时恢复这一比例，并收取规定费用。

在给定情景中比较策略与基准。对每种策略报告：

- 增长指标的中位数；
- 严重损失指标的中位数；
- 增长指标的第 10 百分位；
- 严重损失指标的第 90 百分位。

简要分析一个严重亏损情景，并报告策略发生交易的检查期数占比。判断自动更新权重是否增加价值。

提供一段面向客户的解释，说明一次交易、目标配置改变或人工审核请求，**不超过 50 个英文单词**。

### 1.7 任务三：检验可靠性并定义保障措施

检验一个重要建模假设或交易费率，说明主要建议是否改变。指出一个重要局限，以及一个应触发人工审核或暂停自动策略的条件。说明等待审核期间应用应如何处理组合。

### 1.8 总结与评估规定

给出简洁建议，明确三种组合、客户 A–E 的分配结果、均衡型是否采用自动权重更新，以及主要保障措施。

评估客户 A–E 的建议时，必须考虑各自的投资期限。

可以使用 **情景 1–120** 开发和调整模型。最终策略必须在 **情景 121–180** 上评估，且不得进一步调整。

## 2. 对问题的初步理解

### 2.1 我们要建立的是一套决策流程

这道题的主线是：

```text
客户问卷
  → 判断风险承受能力与资金需求
  → 推荐组合，或转人工
  → 每年根据已知信息检查组合
  → 判断是否值得交易
  → 对异常情况暂停自动决策
  → 用独立情景验证全过程
```

收益高只是评价的一部分。一个策略即使赚得更多，如果严重亏损更大、与客户需求不符、交易理由含糊，也可能不是好方案。

### 2.2 四类动作需要明确区分

| 动作 | 含义 | 例子 |
|---|---|---|
| 保持持仓 | 不交易，允许比例继续随市场变化 | 股票上涨后占比从 40% 升至 43%，暂不处理 |
| 再平衡 | 恢复原来的目标比例 | 将偏离后的比例恢复到原目标 |
| 改变目标 | 重新确定希望长期持有的比例 | 股票目标从 40% 降至 30%，再执行相应交易 |
| 人工审核 | 暂停部分或全部自动决策并交给顾问 | 客户信息矛盾，或风险超出模型适用范围 |

不能把“每年恢复固定比例”直接当作“每年动态优化目标”。报告应分别评价再平衡和目标更新的作用。

### 2.3 客户信息可能相互冲突

以下仅是需要检验的直觉，不是最终客户分配结果：

- A：期限短、损失容忍度低、流动性需求高，倾向保守配置；若保守组合仍不合适，应转人工。
- B：期限与风险容忍度居中，可作为均衡型适配的候选。
- C：期限长、损失容忍度高、流动性需求低，可考虑成长型。
- D：期限长，但损失容忍度较低，不能仅凭期限长就推荐成长型。
- E：损失容忍度高，但期限较短且流动性需求高，需要限制风险或转人工。

题目禁止后续提款，因此不能自行加入提款来“模拟高流动性需求”。建议将流动性需求转化为配置约束或人工审核条件，并明确这是新增建模假设。票据资产也不能被假定为实际购买力无风险。

## 3. 如果由我来做，采用怎样的解题路线？

总体采用 **可解释规则 + 小规模配置搜索 + 严格样本外回测**。优先把基础流程做正确，再考虑动态更新，不预设动态策略一定更好。

### 3.1 先确定信息边界和数据划分

1. 检查情景编号、每个情景的 30 个期间、缺失值、重复记录，以及收益率和通胀率的有效范围。
2. 将情景 1–120 作为开发集；必要时按情景再划分内部训练与验证部分，用于选择参数。
3. 情景 121–180 保留为最终测试集。冻结策略、阈值及主要评价指标后，再进行最终评估。
4. 允许使用开发集估计一套事先固定的市场分布；测试情景运行时，只允许读取该情景截至上一年的数据。

不能将一个情景的年份随机打乱后分到训练集和验证集，也不能将 180 个情景连接成一条 5,400 年的时间序列。

### 3.2 先建立准确的财富与费用账本

每期按以下顺序处理：

```text
读取上年末持仓与已知历史
  → 决定本期动作
  → 记录资产之间实际转移金额
  → 扣除交易费用，得到交易后持仓
  → 应用本期各资产收益率
  → 更新通胀指数和实际财富
```

记交易前名义财富为 `W_before`，资产间转移金额为 `T`，则：

```text
费用 C = 0.0025 × T
交易后财富 W_after = W_before - C
期末财富 = Σ[各资产交易后金额 × (1 + 该资产本期收益率)]
累计物价指数 P_t = ∏(1 + inflation_k)，k = 1,…,t
实际财富 V_t = 当期名义财富 / P_t
```

费用如何从持仓支付、扣费后怎样达到目标比例，需要在实现中统一约定并满足资金守恒。不能一边按完整财富买入目标组合，一边忘记预留交易费用。

所有策略共用同一个账本，避免基准和改进策略使用不同计费方式。

### 3.3 选择少量、含义明确的指标

| 目的 | 初步候选指标 | 解释 |
|---|---|---|
| 投资增长 | 实际年化复合增长率 | 扣除通胀后，财富每年平均复合增长多少 |
| 普通波动 | 年度实际收益率标准差 | 平常涨跌幅度有多大 |
| 严重损失 | 实际财富最大回撤 | 从此前实际财富峰值到后续低点，最多下跌多少 |
| 客户适配补充 | 回撤超过客户容忍度的情景比例 | 说明承受阈值被突破的频率，而非提供保证 |
| 交易行为 | 交易期占比及累计费用 | 策略是否过度交易 |

公式示意：

```text
H 年实际年化增长率 = (V_H / 100)^(1/H) - 1
最大回撤 MDD = max_t [1 - V_t / max_{0≤u≤t}(V_u)]
```

最大回撤非负，越大表示损失越严重；计算时纳入初始实际财富 `V_0 = 100`，使初始费用也影响财富路径。这里观察到的是年度采样的回撤，无法识别年内更深的跌幅，这是需要披露的局限。

先在每个情景中计算增长率与最大回撤，再跨情景计算题目要求的中位数、第 10 百分位和第 90 百分位。不要混淆“情景内指标”和“情景间分位数”。

### 3.4 设计三类组合及透明的客户规则

先用少量固定配置作为起点，例如下表；**这些比例只是待检验候选，不是答案**。

| 类型 | 股票 | 债券 | 票据 |
|---|---:|---:|---:|
| 保守型 | 20% | 50% | 30% |
| 均衡型 | 45% | 40% | 15% |
| 成长型 | 70% | 25% | 5% |

在开发集上，以少量离散权重搜索附近的合理配置，避免为每个客户拟合一套复杂模型。组合规则还要明确采用何种维护方式及费用，不能只给权重而不说明如何持有。

客户评估按以下顺序进行：

1. 按各自期限评估：A 用前 5 年、B 用前 15 年、C 用前 30 年、D 用前 25 年、E 用前 6 年。
2. 为流动性等级设置透明的票据配置要求，具体门槛作为待验证假设。
3. 比较各候选组合的实际增长、最大回撤分布，以及超过客户损失容忍度的频率。
4. 用开发集确定并冻结可接受的超限频率等适配规则；在符合约束的候选中选择合适组合。
5. 如果没有组合满足规则，或客户需求明显冲突，转人工审核，不能强行分配。

最终测试只用于评估已冻结的推荐流程，不能再根据测试集表现替客户挑选组合。

### 3.5 均衡型策略采用分层比较

为了分清改进来自哪里，至少比较以下方案：

| 策略 | 作用 |
|---|---|
| S0：规定的等权年度再平衡 | 必须报告的基准 |
| S1：选定均衡目标的年度再平衡 | 帮助识别目标配置本身的影响 |
| S2：相同均衡目标的条件再平衡 | 判断减少不必要交易是否有价值 |
| S3：允许有限目标更新的策略 | 判断改变目标是否带来额外价值 |

S2 的起点是设置权重偏离阈值，但 **仅超过阈值还不够**，还需通过收益与成本判断。

一种可执行的候选方法是：使用开发集固定的联合收益与通胀样本，估计“保持持仓”和“交易至目标”两种动作下一年的实际净收益分布。对每个动作计算统一分数，例如：

```text
J(动作) = 预期实际净收益
          - λ × 实际净收益方差
          - η × 超过预设损失阈值的预期损失
```

其中交易动作的净收益已扣除费用。`λ`、`η`、损失阈值与保守余量均在开发集内选择并冻结。只有新动作的分数优于保持持仓，并超过预设余量，才执行交易。分数差只是模型估计，不是必然获利保证。

S3 只允许在少量预设的均衡配置之间切换，并采用相同的成本判断。若要加入根据历史更新风险估计的机制，应使用训练先验与截至上年的历史；早期历史不足时回退到训练先验。只有在内部验证显示稳定增益时，才保留这一复杂度。

公平比较时使用相同情景，并报告逐情景的配对差值。若 S3 没有比 S2 带来稳定且有意义的改善，最终建议可以是：**保留固定目标，采用条件再平衡，不启用自动目标更新。**

### 3.6 人工审核必须有具体触发条件和等待动作

建议优先研究两类触发条件：

- 开户时：客户的期限、流动性需求与可承受损失之间无法找到符合规则的组合。
- 运行时：根据截至上一年的信息，风险已超出预先定义的适用范围，例如实际回撤达到警戒阈值，或估计损失风险明显超过客户阈值。

审核触发后不能让回测“缺少下一步动作”。一个简单且可复现的候选约定是：暂停新的自动交易、保留现有持仓、持续监控并通知客户；研究中不假设人工顾问能够完美择时。必须说明该等待规则仍承担市场风险。若设计紧急降风险动作，应将其作为明确策略另行测试，不能默认为卖出票据一定更好。

### 3.7 可靠性检验与严重情景分析

- 主敏感性检验：将费率从 0.25% 分别改为 0.125% 和 0.50%，其余规则保持冻结，判断建议是否改变。费率变化是预先定义的稳健性实验，不用于重选测试集最佳参数。
- 如时间允许，再检验权重偏离阈值小幅变化是否导致结论反转。
- 用同一严重情景比较策略与基准，画出实际财富、回撤、权重和交易时点。情景选择规则事先确定，例如选择基准最大回撤最大的测试情景。
- 交易频率明确分母；建议主指标统计第 2–30 年的 29 次后续检查，初始建仓单独报告。也可补充包含初始建仓的口径，但各策略必须一致。
- 仅有 60 个最终测试情景，尾部分位数可能不稳定；可按情景进行重采样给出不确定性，避免把微小差异解释为确定优势。

## 4. 实施顺序与预期产出
