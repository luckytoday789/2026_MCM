# SOL-034 implementation

This is the missing typed authentication/persistence boundary around accepted
SOL-016. It implements no strategy, calibration, threshold, personalized overlay
or final-data path. Only the three assigned code/test files and this audit tree
are new. All accepted sources, specifications, configurations, historical audits
and the runner remain unchanged. Parent runner owns delivery; no assigned-repo
commit, fetch, push, branch switch, watcher or submission occurred.

The production CLI has only --config, --output and --check. Creation reserves an
absent output root before config/input-capable checks. Its stdlib preflight binds
the real published task, fixed config at E, source C, exact approved source bytes,
and both independently approved producer results. It launches the unchanged
writer checker twice in fresh Python 3.12 children after deleting all
case-insensitive PYTHONPATH entries. Actual argv, exits, timings and log contents/
hashes enter the manifest. A child failure preserves partial diagnostics and
cannot invoke analysis. The assembly import occurs only after successful checks.

The assembly independently validates C/E/P objects and complete source closure,
task/config digests, exact positive queue/chief code and result approvals,
independent numerical review identities, original canonical_git_blob receipts,
all 44 files per producer, current consumed bytes and all five declared CSV
schemas. The primary bundle has exact original HY3-003 imports; doubled has no
imports. Both have unchanged source/input/calibration/policy identity. CSV decoding
uses the accepted writer declarations. A detached metric copy changes exactly
growth_units from percent/year to percentage points per year; values and source
rows are untouched. Every source case/row key and source/bridge hash is recorded.

Only after authentication does the wrapper call unchanged build_analysis_tables
once. It persists all five tables and the manifest with exact recursive JSON
values and explicitly typed paired CSV. A reserved output root contains unique
staging; completed files are created exclusively, and the completed manifest is
published last as the atomic completion marker. This is manifest publication,
not an atomic multi-file transaction. Failed/timeout/oversize staging survives.
Every persisted completed file is bounded at 10 MiB. Production structural counts
9600 / 12000 / 100 / 1 / 30 / 10 are expectations, not observed competition runs.

Read-only --check needs no runtime task or HEAD equality. It authenticates the
saved original Git objects and current bytes, validates the recorded checker
executions, reconstructs the typed bridge, invokes only pure accepted analysis
and compares exact types, float.hex values, nulls, booleans and keys. It does not
launch producer generation/checkers, repair hashes or write evidence. A later
checkout must still contain exact accepted source; an incompatible changed source
requires an isolated accepted checkout.

Schema.json documents a strict future config/task contract. No executable
production config is delivered. Future producer IDs, real receipts/commits and
independent reviews must be supplied only after acceptance. Numerical review
chief records explicitly identify producer_task_id, reviewed_result_commit and
result_verdict=approve, in addition to accepted review code. A completed status
alone cannot satisfy acceptance. Config has source C only; E comes from the task
and P from publication, avoiding self-reference. Existing cancellation and old
historical wording are unchanged.

Generated evidence uses assigned scalar metrics, four scenarios/folds, all eight
modes at two fees and all five horizons. Its private seams are not CLI/config
switches. The local Git fixture makes actual commits C, producer results,
acceptances, E, P and later HEAD, checks a real checkout and stores one small Git
bundle with exact generated bytes. No fake commit tokens or competition input
are used. The audit verifier clones that bundle only into temporary scratch,
authenticates saved bytes, and never modifies original evidence. It independently
checks scalar thresholds, paired versus marginal facts, qualified/profile choices
and all-referral rows. Corruptions are rejected read-only, including rehashed
wrong numbers and type/signed-zero loss.

Fresh boundary children use the unchanged accepted writer source guard and its
actual _check_saved API on the pre-existing small SOL-031 GENERATED fixture only;
those accepted original bytes are inventoried before/after and are never copied
or regenerated. The writer checker performs its own permitted generated-input
calibration/prefix replay in the child. The assembly process performs none.
Actual success and forced nonzero child exits are recorded with module paths.
This is a private synthetic boundary, not a production numerical result.

The first full trial had one erroneous test expectation: a later unchanged task
publication snapshot was expected to fail, although the contract permits it.
That source/log is preserved. An early verifier trial ran before its seal existed
and failed; it is also preserved. Tool/process infrastructure failures and the
initial generated fixture remain in the audit tree. No failed trial was silently
presented as passing. The final clean-environment records carry actual exits,
timings, logs and before/after inventories. Later HY3 assembly execution and chief/
Sol independent numerical acceptance remain separate future work.

The first sealed audit run also detected a verifier-only LF/CRLF boundary error:
the actual temporary checker script was written with Windows CRLF while its
canonical source text was LF. The failed verifier/seal/logs remain preserved;
the read-only verifier now validates either exact encoding without changing
recorded logs, byte hashes or producer/analysis evidence.
