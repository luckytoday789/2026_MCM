# Final evaluation and freeze contract — proposal for independent review

This is a chief proposal, not ops/freeze.json, accepted final code, permission to
open holdout, or evidence that a policy passed development. It extends the
accepted v2 design to the reserved split. Independent design/code reviews and
all actual development gates remain prerequisites. Do not create an empty or
placeholder freeze to make a runner check pass. The machine-readable companion
is final_evaluation_contract_v1.json.

## Decisions completed before holdout access

Accept the exact development generic results, all comparisons and the ten
personalized profile/fee rescreen records, including failures. The primary
Balanced mode comes only from the v2 H30/k=.0025 OOF promotion rule. Each profile's
primary fixed class or referral comes only from its accepted development screen
and own-tolerance rescreen. The .005 records remain separately labelled cost
counterfactuals; they cannot replace a primary choice. Freeze these decisions,
their reasons, exact source rows and accepted worker/chief review commits.

No threshold, class, horizon, fee buffer, prior weight or alternate policy is
selected using final outcomes. All eight predeclared generic modes at both fees
remain visible as fixed diagnostics, even if they were not promoted. These
comparisons do not create a second model-selection opportunity.

Before freeze, independently review explicit final-mode code on generated data.
Existing synthetic/development-only loaders, calibration seams and case APIs
must retain their guards; old approvals do not certify a renamed final split.
The new immutable task must permit each changed path and test the exact final
input boundary, freeze hash, complete scenario keys and refit provenance without
opening competition holdout. Production commands must stay fixed and CPU-only.

Refit one equally weighted annual prior from all 120 development scenarios and
all 3600 development rows, after accepting the development choices. Record its
sorted IDs, ordered row keys, original input SHA256, nominal-row digest and
real-gross digest. All generic and eligible personalized final cases share this
single immutable prior at both fees. No fitting uses final rows; contextual
policies add only their own last min(5,t-1) observations as previously specified.
This is a new all-development calibration, not one of the four OOF calibrations.
The refit is prepared, independently checked and hash-bound before final access.

## Required freeze record and publication order

ops/freeze.json must identify the exact accepted computational source commit
and imported source-file hashes; complete effective policy and numerical
parameters; metrics/units/quantiles/trade reporting; severe selection; fixed
mode/fee/horizon/contrast inventory; frozen primary mode; all ten profile/fee
choices/referrals with source evidence; refit artifact hashes; original input
paths/hashes; explicit commands, output paths and predeclared shard membership;
expected counts and runtime bounds; independent acceptance commits; and the
failure/disclosure rule below. No unresolved/null placeholder may stand for a
required accepted source, selected primary mode or valid comparison rule.
A referral has intentional null class/mode, an explicit reason and zero
personalized simulations; this is distinct from missing information.

1. Commit and push accepted final-capable code, refit evidence and complete
   reviewed run configurations. Keep final_data_open=false.
2. Create the complete freeze from accepted development evidence and pushed
   source. Record a read-only freeze audit and independent review. Push it.
3. Only after those gates pass, chief records the gate opening in control and
   publishes HY3 kind=commands final tasks in a later commit. Each task uses a
   real 40-character pushed base, split=final and the same exact freeze digest.
   The task base may include later ops files; all computational files must still
   match the frozen source. Dependencies, scope, paths, checks and <=1800-second
   budget are explicit. Any shards are disjoint and fixed before first access.

The existing runner digest is SHA256 of the UTF-8 Git blob text after stripping
outer whitespace, matching scripts/coop.py git(...).strip(). This is not a
reserialized JSON digest. Record both this runner digest and canonical blob
SHA256 where appropriate, with names distinguishing them. Freeze audits must
reject changed semantic fields and changed internal bytes. Never mutate a
published task or silently replace a freeze after opening holdout.

## One final evaluation, independent paths and fixed outputs

Read only the locked final subset, IDs 121..180, 60 complete independent paths
of 30 annual observations, after the recorded gate. Each path starts with 100
in bills and fresh state. Preserve exact accounting, all pre-return decisions,
annual simple returns, compounded CPI and all original cost conventions.
Evaluation rows never modify another path's prior. No final-outcome pooling,
validation-fold assignment or training-complement fit is performed on holdout.

Run the eight generic modes at .0025 and .005, retain H=5,6,15,25,30 metrics from
each 30-year ledger, and label the main Balanced comparison H=30. This gives 16
cases, 960 scenario paths, 28800 annual ledger rows and 4800 horizon metric rows.
Keep the same ten fixed contrasts per fee/horizon: 100 comparison summaries and
6000 paired rows. Report paired median growth differences separately from
marginal p10-growth and p90-loss differences. OOF fold-promotion gates are not
reapplied: final fold count/support is inapplicable, never zero, fabricated or a
new promotion criterion. The frozen primary mode remains the reporting choice.

Run a personalized final case only for a profile/fee which passed its accepted
development own-tolerance rescreen. Retain its frozen fixed class, own H,
tolerance threshold and fee. An upstream development referral stays a referral,
with no fallback simulation or re-ranking. Root personalized output has ten
rows; each executed case has 60 metrics and 60*H ledger/decision rows. It may
reuse an exactly identical generic prefix only through a documented lossless
identity check, without changing provenance or claiming a second experiment.

For each executed personalized case, report final p90 loss, p10 growth, strict
loss-tolerance exceedance count/60, median/severe loss and both trade shares.
Apply the unchanged p90<=tolerance AND p10>=0 screens descriptively to the frozen
rule. If either fails, label final_validation_failed_human_review and recommend
human review without selecting a replacement. If both pass, label
frozen_rule_supported_on_final_sample; this is not a guarantee or permission to
trade. Retain all failed policy outcomes. A missing/invalid run is an execution
failure, never a customer referral or successful zero-valued result.

Severe scenario uses greatest exact float maximum real drawdown, then smallest
scenario ID. Peak/trough scan is initial, then post_fee/end; update selected
locations only on strict improvement, preserving earliest maximizing locations
and initial sentinel for zero loss. No comparison epsilon changes this choice.
For display, show the frozen primary's own severe scenario and baseline on that
same path; label baseline's separate severe scenario distinctly. Do not choose
a more attractive scenario after seeing charts. No horizon or tail definition
changes. Each figure/table binds exact source keys, split, units and display
rounding; full precision remains in saved evidence.

## Failure handling, review and delivery

One final evaluation means one frozen inventory, with any predeclared disjoint
shards, not repeated evaluation until a desired result appears. Refuse output
overwrite, preserve failed staging and exact receipt, and use <=10 MiB per file.
Audit/check commands may deterministically reconstruct saved calculations under
the same frozen parameters, read-only, with logged purpose; they do not permit
new variants, repeated selection or fitting on final data.

After any access attempt fails, log exact source/task/freeze/inputs, what was
read or computed, failure time/reason, partial results and affected claims.
Do not reset the gate or describe a subsequent execution as untouched. A genuine
software fix needs an independently reviewed minimal patch and new immutable
task/configuration referring to the original freeze plus an explicit correction
record. Preserve the old freeze and outputs. Compare affected/unaffected
behavior, disclose exposure and whether any outcome changed, and prohibit
policy/parameter tuning. A bad policy result requires honest reporting/referral,
not a software retry. If blocked, checkpoint and request actual needed help.

Sol independently checks exact HY3 final commits, representative complete
ledgers, inflation, fees, no-lookahead/refit separation, tail/paired statistics,
severe locations, personalized thresholds/referrals and full counts/hashes.
Chief accepts exact commits only after those gates pass. Final claims cite
accepted evidence, including negative findings and any corrected evaluation.
The <=10-page English A4 report, >=11pt type, AI disclosure and <=50MB source ZIP
need independent content checks and rendered-page/package verification. Keep
member names/IDs in the local delivery copy under the recorded GitHub restriction.
The human team leader submits; no automatic upload is authorized.
