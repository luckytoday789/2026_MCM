reviewed calibration mathematics, but do not treat a synthetic-labelled helper
manifest as proof of production origin or blindly relabel it. The production
adapter creates its own manifest from verified input evidence and exact fold
records. Any necessary shared-core refactor requires its own narrow tests and
review; an old calibration approval never certifies changed code. Each fold must
have 90 training IDs, 30 evaluation IDs and 2700 ordered training rows, immutable
and shared across both fees. Record sorted IDs, row keys, nominal-row digest and
real-gross digest with the accepted canonical serialization.

summary.csv, decisions.csv and target_scores.csv where applicable. Empty baseline

cost-aware file as an empty baseline. Include calibrations.json, run_manifest.json,

never fabricate a missing case to generate a summary. The analysis bundle uses
all sixteen cases, 100 comparison summaries, 12000 paired rows, 30 profile candidate
rows, ten provisional assignments and one primary choice with separate sensitivity.

Before beginning, refuse any existing output directory. Write new artifacts in a
unique staging location under the requested new root; publish completion only
when all artifacts and checks pass. On exception preserve partial files, original
logs and an explicit failed status/diagnosis at that unique path. Never overwrite
prior successful or failed evidence. Each artifact <=10485760 bytes; enforce actual
bytes, not an estimate. Record measured runtime against the immutable task budget.
Do not extend an in-flight task or silently subdivide/restart it after a failure.

## Read-only verification and independent acceptance

--check opens the exact saved evidence and recorded source. It writes nothing,
including refreshed manifests, hashes or bytecode. Verify all expected files,
counts, keys, units, source/config/input hashes, imported references and calibration
memberships. Independently reconstruct fee/holdings/CPI identities and representative
metrics; replay nonbaseline policy decisions from exact prefixes where useful.
Reference imports use prior accepted evidence and direct ledger checks, without
launching the old baseline experiment. A checker using the same production
function alone is not independent mathematical validation; remote Sol review of
actual HY3 output is still mandatory.

Before authorizing HY3, demonstrate missing-file, altered-numeric, false-source,
wrong-config, duplicate-key, bogus-count and incomplete-status rejection on scratch
copies, while all original saved bytes remain unchanged. Failed generations and
negative findings are preserved. Strict final-data guards stay closed. After
chief acceptance, HY3 receives only exact reviewed fixed commands; the Sol
review task then pins the precise HY3 receipt commit and independently reconstructs
selected ledgers, comparisons and profile screens. No output is accepted solely
because its manifest says completed.
