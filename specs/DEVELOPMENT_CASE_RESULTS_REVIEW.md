# Independent review handoff for fixed development case results

Chief preparation only. This note defines evidence to request when each actual
HY3 case result arrives. It is not a task, execution configuration, accepted
result, investment conclusion, parameter change or final-data permission.
An immutable Sol review task must pin the real producer task/digest, exact
result commit, receipt, configuration and source blobs after publication.
Preserve the failed writer/review attempts and all future negative outcomes.

## Review each fixed group promptly

Review primary and doubled separately as their receipts arrive; do not hold a
completed primary bundle merely because doubled is running. Each review uses
only its producer's authorized development input and saved output. Do not rerun
the original HY3-003 baseline experiment. The primary group contains five newly
computed policies and three authenticated imports; doubled computes all eight.
Each group has exactly 44 files, 28,800 ledger rows, 4,800 metric rows, 40 summary
rows and 18,000 decision rows. Up to 24,000 score rows are permitted; actual
review latches can reduce this count. These are expectations, not measurements.

Verify the actual immutable task, owner/attempt/branch, canonical task digest,
base E, publication P, accepted source C, config Git hash, original input hash,
Python 3.12, command exits and parent/result relationship. E must already exist
on origin/main before task publication. Require only assigned result paths plus
parent-generated handoff paths, all 44 regular files, exact staged Git hashes,
complete typed keys, per-file bytes <=10 MiB and measured runtime within the
fixed limits. Status branches are metadata only. A failed receipt stays failed;
retain its partial output and diagnosis rather than promoting successful parts
as a completed bundle.

Run the exact writer --check in a fresh Python 3.12 subprocess without any
case-insensitive PYTHONPATH variable before importing separate review modules.
The writer's unlisted-import guard remains unchanged. Record actual argv,
return code, duration and logs; use the exact pinned producer source in an
isolated checkout if current main has changed. Compare source/config/input/
result inventories before and after; no regeneration, hash repair or overwrite.
A successful producer check is necessary but does not replace independent
arithmetic or establish numerical acceptance by itself.

## Independently reconstruct decisive numerical facts

Implement the reviewer arithmetic without calling the producer's accounting,
metric, calibration, case or policy functions to create expected values.
Use Fraction/Decimal or explicitly justified high-precision scalar arithmetic;
record actual checked keys, expected/observed values and error tolerances.
Existing accepted independent oracles may support the review, but their replay
alone does not bind new HY3 result bytes.

1. Validate all four evaluation folds and their 90-scenario complements. Each
   training prior has exactly 2,700 ordered annual rows, uses all 30 years of
   those scenarios, and excludes the whole evaluation fold. Rebuild training
   and derived-real-gross digests from original permitted bytes. Priors are
   independent of customer H and shared unchanged across the two fee groups.
2. Reconstruct representative complete paths across all four folds, including
   IDs 1..4 in each newly computed mode, plus each H30 severe scenario and any
   paths needed to cover observed initial deferral, target change and latch.
   Report absent actions as absent; do not manufacture their occurrence.
   Check keep preserves dollars, T=W/2*sum(abs(w-u)), fee=k*T before returns,
   post-fee holdings=(W-fee)*w, exact compounded CPI, and both post-fee/year-end
   real observations. The 1e-10 trade-count threshold never cancels a fee.
3. Independently recompute every scenario metric from saved ledgers: H-specific
   real CAGR, sample annual-real-return standard deviation (ddof=1), maximum
   real drawdown including initial 100 and post-fee points, fee sum and both
   trade denominators. For policy modes also verify action/diagnostic links,
   latch year, first deployment and executed target-state changes.
4. Recompute every summary from its 120 scenario metrics, using linear
   quantiles and the locked exact severe-case tie rule. Verify all five H,
   explicit units, deterministic keys and baseline null diagnostics. Do not
   treat a p90 drawdown as a worst-case bound or statistical confidence limit.
5. Independently score representative pre-decision states and observed action
   boundaries using gamma=4, correct empirical weights, and same-scenario
   completed observations only. Check contextual n=min(5,t-1), prior mass 15,
   adaptive alternatives first eligible at year 6, the doubled-cost decision
   buffer and the single actual fee. Verify strict keep hurdle, global-max
   anchored tie order and active-target updates, including tiny transfers.
6. Verify the human-review latch uses only observed drawdown through t-1,
   starts at observed drawdown >=25%, never resets, and keeps dollar holdings
   with zero fees thereafter while annual returns still apply. Use isolated
   copied/generated fixtures to perturb future observations and confirm earlier
   decisions stay unchanged. Preserve those fixtures; no changed production
   input may be reclassified as accepted results.

Primary additionally authenticates original HY3-003 receipt and all five source
artifact blobs, then proves each imported value is unchanged after its explicit
typed/name/unit bridge. Three reference sidecars are empty and inapplicable;
there is no baseline callback invocation. Doubled has no imports and charges
0.005 in both scoring and accounting. Cross-fee comparisons must not assume
identical holdings, trades, latches or outcomes.

## Preserve failures and keep acceptance narrower than selection

Use compact isolated corruptions for missing file, changed numerical value,
wrong source/config/task identity, duplicate key, false count and incomplete
status. Where useful rehash a wrong metric to test numerical checking beyond
simple hash matching. Rejection is read-only; record before/after inventories.
Do not duplicate complete large bundles or alter historical checker evidence.
A portable review --check must bind the exact task/base/source/result bytes,
replay meaningful arithmetic and reject corruption after HEAD advances without
.runtime/task.json. Save every actual command/failure and any untested boundary.

Chief independently checks selected scalar fixtures and reviews the exact Sol
commit before accepting either producer. Record its precise reviewed SHA and
acceptance evidence in the queue. Independent negative findings remain useful
accepted evidence when clearly distinguished from result/code approval.

Neither group review chooses a policy or assigns a customer. Only the later
accepted analysis assembly consumes both accepted groups into the full grid:
9,600 metrics, 12,000 paired rows, 100 gates, 30 screens and 10 provisional
recommendations. Retain every contrast/failed control. Primary k=0.0025/H30
alone determines the research-selected Balanced variant; doubled-cost results
assess that same choice and never substitute a new winner. Profile screening
uses each own H and the fixed classes. Personalized own-tolerance follow-up,
independent review, freeze and final evaluation remain separate gates.
